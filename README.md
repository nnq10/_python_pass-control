# Контроль пропусков

Desktop-приложение на Python для учета пропусков. Проект помогает вести базу
посетителей и сотрудников, печатать пропуска, работать с QR-кодами, сканировать
их через камеру, импортировать данные из Excel и делать резервные копии.

## Возможности

- создание, редактирование, поиск и архивирование пропусков;
- генерация QR-кодов и печатных форм;
- сканирование QR-кодов через камеру;
- временные пропуска и учет возврата;
- импорт данных из Excel;
- журнал действий и статистика посещений;
- управление пользователями и ролями;
- резервное копирование и восстановление данных;
- проверка целостности данных и очистка лишних файлов.

## Требования

- Python 3.10 или новее;
- Windows, Linux или macOS с доступом к графическому интерфейсу;
- камера, если нужен режим сканирования QR-кодов.

Зависимости перечислены в `requirements.txt`:

- `customtkinter` - интерфейс приложения;
- `Pillow` - работа с изображениями;
- `qrcode[pil]` - генерация QR-кодов;
- `openpyxl` - импорт из Excel;
- `opencv-python` - работа с камерой.

## Установка

```powershell
git clone https://github.com/nnq10/_python_pass-control.git
cd _python_pass-control
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Запуск

```powershell
python pass_control.py
```

При первом запуске приложение создаст рабочие файлы в папке `data/`.

## Данные приложения

Рабочие данные хранятся локально в `data/`:

- `passes.db` - база пропусков и журналов;
- `users.json` - пользователи и хеши паролей;
- `settings.json` - настройки приложения;
- `photos/` - фотографии;
- `qrcodes/` - QR-коды;
- `prints/` - готовые файлы печати;
- `backups/` - резервные копии;
- `app.log` - журнал работы приложения.

Содержимое `data/` не коммитится в Git. В репозитории остается только
`data/.gitkeep`, чтобы папка существовала после клонирования.

## Тесты

```powershell
python -m unittest discover -s tests -v
```

## Структура проекта

```text
pass_control.py      # точка входа
ui_widgets.py        # общие UI-компоненты старого уровня
app/
  core/              # пути, настройки, логирование
  pages/             # экраны приложения
  services/          # бизнес-логика, БД, QR, бэкапы, печать
  ui/                # общие виджеты интерфейса
static/              # статические ресурсы
tests/               # автотесты
data/                # локальные рабочие данные, не коммитятся
```

## Безопасность данных

Не публикуйте содержимое `data/` в открытом репозитории. Там могут находиться
персональные данные, фотографии, база пропусков, настройки и файлы пользователей.

Пароли пользователей не хранятся открытым текстом: используется PBKDF2-SHA256 с
солью.

## Резервные копии

Приложение может создавать автоматические и ручные бэкапы. По умолчанию старые
архивы очищаются, чтобы хранить ограниченное количество последних копий.
